# Part 2: API & Data Access Layer

**Files Discussed:**
- `JavaUI/src/com/notegraph/ui/api/ApiClient.java`
- `JavaUI/src/com/notegraph/ui/api/ApiModels.java`

Professor, the second part of the software handles data synchronization. Because we are building a decoupled client, the frontend must rely entirely on network requests to the Spring Boot REST API.

In **`ApiClient.java`**, the logic uses the Singleton design pattern. I instantiate `private static ApiClient instance`, ensuring the entire application shares one standard HTTP client and doesn't exhaust socket connections. For the network code, I utilized the native Java 11 `HttpClient`. 

The core authentication logic resolves around JSON Web Tokens (JWT). When the user logs in, the backend responds with a token. I capture that string and store it in a `private String jwtToken` variable. For every subsequent request—for example, calling `getWorkspaceNotes()`—my logic intercepts the building of the `HttpRequest`. It specifically calls `.header("Authorization", "Bearer " + jwtToken)`. This proves to the backend that the user is authorized. 

I also built rigorous error-handling logic into this client. After `client.send()` executes a request, I check `response.statusCode()`. If the backend returns a 200 series code, it proceeds. But if my logic detects a 400 (Bad Request) or 401 (Unauthorized), it grabs the error message array out of the JSON response body and throws a `RuntimeException`. This specifically prevents the UI panels from crashing silently; instead, the UI catches the exception and displays the exact error message to the user.

To manage the raw JSON text arriving over the network, I wrote **`ApiModels.java`**. The logic here is built around the Google Gson library. Rather than writing thousands of lines of manual JSON parsing code (checking for braces and quotes), I defined static inner nested classes like `public static class NoteDto`. 

The specific logic dictating this file is reflection-mapping. I declared variables inside these classes (e.g., `public String title;`, `public String content;`) whose names *exactly* match the key strings generated by our Spring Boot backend. When `ApiClient` receives the raw string from the server, I run the logic `new Gson().fromJson(response, NoteDto.class)`. Gson dynamically scans my Java class, finds matching variables, and injects the JSON data directly into strongly-typed Java objects. This totally decouples the UI panels from parsing mechanics; they just receive fully populated Java objects ready to be displayed.
